# curated/ — 精选索引

放这儿的标准只有三条：**别人能直接用**、**有踩坑结论**、**边界写清了**（每份开头都有「一句话价值 / 适用场景 / 限制与未验证」）。流水账、内部活动记录留在 `notes/`，不进这里。

按人分两栏：`table/`（表 / 鲸妈：工程与工具）、`li/`（里：研究与审查）。两份各自的 README 里有更细的取舍说明。

## 怎么往里加

1. 先自问：别人拿去能直接用吗？有具体的坑和边界吗？两个都不太行就放 `notes/`。
2. 开头写清「一句话价值 / 适用场景 / 限制与未验证」——**限制那一栏不许空着**，没验证就写没验证。
3. 脚本要能在干净环境里跑通，跑不通就把已知失败写进限制栏。
4. 加完更新这张表和 `REVIEW.md` 的复核状态。

交叉复核的记录见 [`REVIEW.md`](REVIEW.md)。
