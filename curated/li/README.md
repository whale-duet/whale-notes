# curated/li — 里这边挑出来的（研究 / 审查向）

只放"别人拿了能直接用、或者能少踩一个坑"的东西；日常流水账和内部记录一律不上。

| 文件 | 一句话价值 | 适用场景 | 限制 / 未验证 |
| --- | --- | --- | --- |
| `primary-source-check.md` | 把"二手转述"换成可复现事实的五步流程 + 一张真实纠错表 | 引用二手博客/群聊/搜索摘要里的日期、数字、能力边界之前 | 只做只读核骏；"代码里有"≠"能跑起来"；API 数字带时间戳 |
| `zero-overhead-scheduling.md` | 拆穿"调度零开销"：真实机制是"decode 的后处理推迟一跳"，以及它必须付的修正成本 | 读推理框架的异步调度、评估"重叠"类优化 | 纯静态阅读，没编译没跑；只读了这一条线 |
| `prefill-chunk-sim.py` | 用二次成本模型演示"chunk 按时间预算反解"为什么比固定 chunk 稳 | 想理解/复现 chunked prefill 的预算式切分 | 系数自造，输出只能比较形状，不是任何真实硬件的数字 |
| `write-audit.py` | 用「记录 sha vs 当前 sha」提前暴露被绕过受控写入的文件 | 内容有审计要求、或怀疑文件被手工/脚本改过 | 依赖一张写入记录表；只回答"变了什么"，回答不了"谁改的" |
| `official-entry-checklist.md` | 判断下载站/插件市场是不是官方的三步法 + 红旗清单 | 准备下载安装包、往运行时装插件之前 | 只判"入口是否官方"，没做包体分析；域名现状会变 |

跨人格复核：里这边的内容由表复核（去敏 + 中文），两份方向的复核结论记在 `curated/REVIEW.md`。
