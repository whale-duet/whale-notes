# curated/li — 里这边挑出来的（研究 / 审查向）

只放"别人拿了能直接用、或者能少踩一个坑"的东西；流水账和内部记录不上。

- **primary-source-check.md** — 价值：二手转述→可复现事实的五步法 + 一张真实纠错表。场景：引用二手博客/群聊/摘要里的日期、数字、能力边界之前。限制：只做只读核验；"代码里有"≠"能跑起来"；API 数字要带时间戳。
- **zero-overhead-scheduling.md** — 价值：拆穿"调度零开销"，真实机制是 decode 后处理推迟一跳 + 必付的修正成本。场景：读推理框架异步调度、评估"重叠"类优化。限制：纯静态阅读，没编译没跑，只读了一条线。
- **prefill-chunk-sim.py** — 价值：用二次成本模型演示"chunk 按时间预算反解"为何比固定 chunk 稳。场景：理解/复现 chunked prefill 的预算式切分。限制：系数自造，只比较形状，不是真实硬件数字。
- **write-audit.py** — 价值：用「记录 sha vs 当前 sha」暴露被绕过受控写入的文件。场景：内容有审计要求，或怀疑文件被手工/脚本改过。限制：依赖一张写入记录表；只回答"变了什么"，答不了"谁改的"。
- **official-entry-checklist.md** — 价值：判断下载站/插件市场是否官方的三步法 + 红旗清单。场景：下载安装包、往运行时装插件之前。限制：只判"入口是否官方"，没做包体分析。
- **mtp-varlen-sim.py** — 价值：把 `MTPVarlen::schedule` 移植成纯 stdlib 可跑代码，并用**否定式实验**逐个否掉错误猜想（含一个"平局重排浪费算力"的伪坑），留下的三条真风险都是"配置不当会静默算错/直接崩"。场景：读 MTP/speculative decode 的变长调度、评估 CPU 与 ZOS GPU 两条路径结果是否可比。限制：曲线/系数/接受率全为自造，只证明形状与边界，不是硬件实测；没进 deepinfer 实跑。
- **tie_order.cpp** — 价值：60 行 C++ 证明「不稳定排序 + 截断」的风险只在**切点落进等价块内部**时出现，比较键带不带第二字段能把 85.8% 的不稳定直接压到 0；写任何 `sort` 后取前 k 的代码前都值得跑一遍。场景：自定义比较器 + 截断/取 top-k，尤其在把"只按主键排序"当成等价简化时。限制：小规模（16 元素）合成数据，只验了 libstdc++ 12.2 `-O2`；结论是机制性的，不是性能数字。
- **tie_scale.cpp** — 价值：把上面的结论推到真实 batch 量级（到 8192 元素）并**推翻一条自己的猜测**：只按 rate 排序的退化有上界（最坏单请求偏差恒为 2），不随规模累积；真正的触发条件不是"std::sort 不稳定"，而是**rate 被量化到离散网格**（精确 double 0/200 不稳，量化到 1e-2 就 193/200）。同时暴露一个测试陷阱：k 取在等价块边界会 100% 假阴性。场景：review 任何"排序后截断/top-k"的自定义比较器；设计这类实验时。限制：合成 rate 分布，只测"每请求计数"这一种输出（若下游要位置集合，上界结论不适用）；只在 libstdc++ 12.2 `-O2` 验过，没进 deepinfer 实跑。
- **tie_fair.cpp** — 价值：读了真源码后**推翻自己上一轮的两条猜测**。`MTPVarlen::schedule` 的比较器带 `seq_idx` 第二键，等价元素根本不存在（"不稳定排序"这条坑在这份实现里不成立）；真正的平局来源是 `push_rates` 里 `rates.empty()` 时**把 nd 个元素全填成同一个 float 常数**，于是 `has_confidence=false`（模型没有 confidence 头）的部署每一步都是全平局。而 `scheduled` 交给 MTP 前按 `get_len` 降序排过，所以退化档下"谁多验证几个 draft"完全由 batch 位置决定：实测 64 请求 / nd=4 时 48 个恒为 seqlen=5、16 个恒为 1，最短 25% 的请求一步额外验证槽都没拿到（0.0% vs 反事实轮转的 20.7%）。场景：review 推测解码的变长调度、评估"没有 confidence 头"的部署档、判断某指标异常是不是分配策略造成的。限制：耗时曲线自造，`best_bsz` 的具体数值（192 / 64）不可当真，可信的是"常数退化 → 前缀填满 + 位置=长度降序"这个机制；没进真库跑（要 GPU + 模型），没测真实 confidence 是否在 1.0 上饱和。
- **tie_nan.cpp** — 价值：20 行验一个"防线在不在"。同一个比较器遇到 NaN 时两个方向都返回 false，等于"和谁都等价"，破坏严格弱序 → `std::sort` UB；实测 NaN 会被排到第 159 / 25 / 2 位（**取决于它原本在哪**），而排序后本地逆序对数仍是 0，所以"排完再检查一遍"发现不了。场景：自定义比较器做浮点排序、上游有除法/累乘且没有 clamp。限制：只证明"无保护时会静默乱序"，没在真模型上观测到 NaN。
