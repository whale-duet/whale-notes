# curated/li — 里这边挑出来的（研究 / 审查向）

只放"别人拿了能直接用、或者能少踩一个坑"的东西；流水账和内部记录不上。

- **primary-source-check.md** — 价值：二手转述→可复现事实的五步法 + 一张真实纠错表。场景：引用二手博客/群聊/摘要里的日期、数字、能力边界之前。限制：只做只读核验；"代码里有"≠"能跑起来"；API 数字要带时间戳。
- **zero-overhead-scheduling.md** — 价值：拆穿"调度零开销"，真实机制是 decode 后处理推迟一跳 + 必付的修正成本。场景：读推理框架异步调度、评估"重叠"类优化。限制：纯静态阅读，没编译没跑，只读了一条线。
- **prefill-chunk-sim.py** — 价值：用二次成本模型演示"chunk 按时间预算反解"为何比固定 chunk 稳。场景：理解/复现 chunked prefill 的预算式切分。限制：系数自造，只比较形状，不是真实硬件数字。
- **write-audit.py** — 价值：用「记录 sha vs 当前 sha」暴露被绕过受控写入的文件。场景：内容有审计要求，或怀疑文件被手工/脚本改过。限制：依赖一张写入记录表；只回答"变了什么"，答不了"谁改的"。
- **official-entry-checklist.md** — 价值：判断下载站/插件市场是否官方的三步法 + 红旗清单。场景：下载安装包、往运行时装插件之前。限制：只判"入口是否官方"，没做包体分析。
- **mtp-varlen-sim.py** — 价值：把 `MTPVarlen::schedule` 移植成纯 stdlib 可跑代码，并用**否定式实验**逐个否掉错误猜想（含一个"平局重排浪费算力"的伪坑），留下的三条真风险都是"配置不当会静默算错/直接崩"。场景：读 MTP/speculative decode 的变长调度、评估 CPU 与 ZOS GPU 两条路径结果是否可比。限制：曲线/系数/接受率全为自造，只证明形状与边界，不是硬件实测；没进 deepinfer 实跑。
- **tie_order.cpp** — 价值：60 行 C++ 证明「不稳定排序 + 截断」的风险只在**切点落进等价块内部**时出现，比较键带不带第二字段能把 85.8% 的不稳定直接压到 0；写任何 `sort` 后取前 k 的代码前都值得跑一遍。场景：自定义比较器 + 截断/取 top-k，尤其在把"只按主键排序"当成等价简化时。限制：小规模（16 元素）合成数据，只验了 libstdc++ 12.2 `-O2`；结论是机制性的，不是性能数字。
