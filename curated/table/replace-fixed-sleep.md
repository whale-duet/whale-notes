# 把「睡一会儿再断言」换成「等对方自己报告」

- **一句话价值**：测试里那句 `await sleep(300)` 猜的不是产品要多久，而是「对方做完了没有」；换成被测方自己发出的那个信号，
  再用「窗口长度按它在等哪一段保护算」，可以让这类用例从「红灯随机」变成「红了就指向真实那一行」——本文四种锚点是实跑出来的，
  还附一条反直觉的：**删掉等待后测试可能依然全绿**，所以验收不能靠「删了会红」。
- **适用场景**：一个用例里有子进程 / 另一个连接 / 后台队列，你在「起完之后睡一下再断言」；或者被同事 review 到
  `sleep(200)` 写在断言前一行。
- **限制与未验证**：全部是同一台 Linux 上 Node 22 + vitest 4 + SQLite（同机同文件）的实测；文件锁语义换到 Windows/macOS
  没验；每个锚点都要能改 fixture 或被测方（不能改的第三方进程就退化成轮询 + 期限）；数字是某一台 8 核机器上的量级，别当基准。

## 一、先分清两种「固定等待」

1. **没有期限的等待循环**：`while (!existsSync(held)) await sleep(50)`。好认，也容易做成静态检查（循环体里有没有
   `deadline` / `Date.now()`）。
2. **一行 sleep 加一条断言**：`await sleep(300); expect(rows()).toEqual([])`。这是同一个猜，只是没穿循环的外套。
   文本扫描能把它列出来，但**列出来不等于修好**：真正的改进是给它一个锚点。

值得记住的量级：一个 85 文件的项目里，这类固定等待清理前有 66 处（31 个 spec），其中「没有任何可观测锚点」的负向窗口 7 处。
一轮改一处，每处都要先证明「旧写法测的到底是什么」——这活儿的成本在核验，不在改。

## 二、四种可观测锚点（都实跑过）

### 1. 子进程自报「我到达了」

子进程在碰到竞争点**之前**写一个文件（或被 Proxy 包住的写路径里记一行日志），父进程等这个报告出现，再起算窗口。

```ts
// 子进程侧：open 事务之前先报到
writeFileSync(ATTEMPT_FILE, String(process.pid))
// 父进程侧：等报告，再谈窗口
await untilAttempt(ATTEMPT_FILE, { timeoutMs: 10_000 })   // 报告没来就红在「它没走到这里」
```

关键点：**报告必须早于竞争点、晚于进程真正开始干活**。只报「进程起来了」不够——进程起来了但还没走到锁，你依然在赌。

### 2. 锁「真的放开了」：另开连接试写才算

进程被 `SIGKILL` 之后，`waitForExit()` 返回不代表文件锁没了。

```ts
async function lockFree(onAttempt: () => void, timeoutMs = 10_000) {
  while (Date.now() < startedAt + timeoutMs) {
    onAttempt()
    const probe = new DatabaseSync(dbPath)
    try { probe.exec('BEGIN IMMEDIATE; COMMIT;'); return } catch { /* BUSY：还没有 */ } finally { probe.close() }
  }
  throw new Error('waited for the write lock to be released')
}
```

外加一条**自证用例**：自己先占住写锁，探针问两遍必须都回答「没放开」，`COMMIT` 之后才允许说放开。没有这条自证，
锚点写错了也永远绿。

### 3. 队列「自己回答」：从调用方那一侧记账

「暂停时卡片被扣住」这类用例，锚点不是时间，而是被测方对 `paused()` 的那次询问本身：fixture 的 `paused()` 每次被调用就记一行
（`pause held` / `pause clear`），用例先等本进程出现一条 `pause held`，再断言没有候选被取走。

要点：**观察点放在被测代码必然经过的那条路径上**（这里是「有到期行时才调用 limit」），而不是放在用例自己猜的时间点。

### 4. 消费端「读完了那一行」

发布/订阅风格：生产端写入一行，用例原本 `await sleep(150)` 再断言「没重复处理」。改成让消费端在处理完之后报一条
（`settle attempt` / `consumed`），用例等这条报告，再断言后面没有多余的处理。

要点：锚点钉的是「读到了」，不是「那条 `if` 写没写」。变异实验能区分这两件事——把 drop 那行挪到 `receive()` 之后，
锚点依然咬得住（红在「读到了之后还多处理」），把守门条件去掉也会红。

## 三、窗口长度：先问「它在等哪一段保护」

这是最容易写错、也最反直觉的一节。

- **负面教材**：某用例写 `await sleep(200)` 想表示「锁还被我占着，写没成功」，实测这 200 ms 实际睡了 **5008 ms**。
  原因是同进程里 `DELETE` 一撞锁就进 `busy_timeout=5000` 的**同步**等待，事件循环被堵死，`setTimeout` 的回调排在后面。
  于是断言读到的是「写已经以 BUSY 失败之后，行还挂着」——注释里那句「锁住期间仍然声称拥有」从来没成立过，它一直是绿的，
  因为提交之后重试把行删了。
- **正确的算法**：窗口长度 = `busy_timeout` **加上**重试阶梯 **加上**一点余量，同时还要满足「窗口小于两条保护之和」，
  否则第一次尝试自己就能等满 `busy_timeout`，阶梯根本没机会跑。把这两个不等式写进用例：

```ts
expect(window).toBeLessThan(BUSY_TIMEOUT_MS + ATTEMPT_LADDER_MS)  // 阶梯必须还在等
expect(window).toBeGreaterThan(BUSY_TIMEOUT_MS)                   // 但它等不过第一条保护
```

第一次写这条例子时窗口只取「阶梯 + 400ms」，变异（把阶梯计数改成永真）**是绿的**——因为 `busy_timeout` 顶住了。
窗口的长度决定这条用例到底在测哪一层保护。

## 四、验收：变异三态，别只看「删掉会不会红」

每条改完都用变异验：改一处源码 / 改一处 fixture，跑这一条用例，看它红不红、红在哪一行。

- **M1 / M2 应该红在同一条断言**：例如 M1「不试锁直接 return」、M2「把 BUSY 当成成功」，两条都得红在
  `expect({ settled, asked })` 那一条——说明锚点是唯一的、钉的是同一件事。
- **M3「删掉等待」全绿是常态，不是失败**：三次实验里，把 `kill()` 之后的那段等待整个删掉，4 条用例仍然全绿。
  因为「等」在旧代码里等的本来就是一个已经成立的条件。**所以这轮不是修 flake**：验收靠自证用例，
  不靠「删掉就红」。把这条写进提交说明，能省掉下一轮同样的误会。
- 变异脚本要**先 `cp` 原件再改**：`git checkout --` 会把未提交的补丁一起还原，我因此重跑过一次补丁脚本。

## 五、把清单做成棘轮

修到「没有无锚点窗口」之后，清单本身会重新长回来。做成两条闸：

1. **基线文件**：每条仍然保留的固定等待都写清「它在等什么 / 为什么观察不到」；新增的等待让测试红并点名文件和语句
   （用「文件 + 语句」做身份，不用行号，行号会被上面的编辑挤走）；基线里已经没有对应等待的条目报 stale。
2. **不许「写基线即通过」**：理由字段空着（或太短）也算失败，否则 `--write-baseline` 会把「我没看」变成绿灯。

## 六、零碎坑（都踩过）

- `pgrep -f 'vitest'` 会匹配到**遗留的排队 shell**自身（`while pgrep …; do sleep …; done`），队列永不放行；判忙要连 argv 一起看。
- vitest 4 没有 `--reporter=basic`（报 `loadCustomReporterModule` + 退出码 1，看着像红）。
- 容器里默认 node 18 起不来 vitest 4（`node:util` 的 `styleText`），要显式用 node 22 的 PATH。
- 健康检查行要按前缀数，别按整行相等数：`health notice error <detail>` 用整行相等永远是 0，会让变异检查假绿。
- 同时跑两个全量 `--coverage` 必然撞出 5s / 10s 超时；开全量之前先看有没有别人的跑在跑。

## 七、适用范围与边界

- 只在**能改 fixture / 被测方**的前提下成立。改不了第三方进程时，退化成「轮询 + 期限 + 超时报出缺什么」，
  比固定 sleep 强，但仍不是事件级锚点。
- 文件锁、信号投递（`SIGSTOP` / `SIGKILL`）这类时序在同一台 Linux 上可复现；跨平台、网络文件系统没验。
- 文中的毫秒数只说明量级与不等式，不当性能数字。
