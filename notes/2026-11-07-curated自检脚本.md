# curated 自检脚本：把「去敏 + 边界」从人工通读变成一条命令

- **一句话价值**：`scripts/curated_lint.py` 一条命令扫出目录里的私有路径 / 凭据 / 邮箱 / 内网地址 / 非 UTF-8，
  外加「价值 / 适用场景 / 限制」三件套缺失；14 份文件人工复核一遍要半小时，现在是 0.1 秒。
- **适用场景**：往公开仓库上传文档或脚本之前；接手别人写的稿子；怀疑某份文件里混了机器路径。
- **限制 / 未验证**：规则是正则黑名单，只能查「见过的那几类」形近于泄密的东西，
  查不出语义层面的泄密（例如把别人隐私改写成正常句子）；中文形近字（`统`→`绗`）它查不出来，
  只能查 U+FFFD；`.cpp`/`.py` 若按索引表写价值、正文只写限制，会报 3 条 missing-warning，属预期噪声。

## 它为什么存在

前几轮 `curated/` 前后 14 份，全靠人工 `grep` + 通读。人工的问题是**不一致**：
同一份文件昨天查了路径、今天忘了查邮箱；而且**复述缺陷时会连缺陷一起搬进公开仓库**——
这次就是这么被自己抓出来的。

## 用法

```bash
python3 scripts/curated_lint.py curated            # 人读格式，error 会以非 0 退出
python3 scripts/curated_lint.py . --json           # 机器格式，接 CI 或别的脚本
python3 scripts/curated_lint.py . --strict         # warning 也算失败
python3 scripts/curated_lint.py --self-test        # 内置夹具自测，不碰真实文件
```

退出码：`0` 干净（默认 warning 不拦）/ `1` 有 error（或 `--strict` 有 warning）/ `2` 用法或路径错误。

## 三条设计决定（都是踩过坑才这么写）

1. **输出只给位置、规则名和前 4 个字符**：`[ERROR] REVIEW.md:16 posix-home-path — 私有绝对路径 (/hom…)`。
   自检工具自己不能变成泄密源——它一旦打印整行，把报告贴进 issue 就等于二次公开。
2. **例外写在文件里，不写在脚本里**：命中行带 `lint:allow` 就放行。
   想减免检，改脚本（等于对所有人放宽），加标记（等于这一行留痕），选后者。
3. **私网 IP / 手机号只 warning**：示例数字极易误伤（`172.16` 可能是版本号，11 位数字可能是哈希前缀）。
   校验规则宁可漏报让人判，不要误报让人把工具关掉。

## 自测覆盖什么

`--self-test` 在临时目录造 4 个夹具：干净 md、脏 md（5 类各一条 + 1 条 `lint:allow`）、
非 UTF-8 的 md、二进制 .bin。断言：干净零报错、脏的 4 类命中且内网只 warn、
`lint:allow` 生效、输出被打码、非 UTF-8 报 error、有 error 时退出码非 0、干净目录退出码 0。
